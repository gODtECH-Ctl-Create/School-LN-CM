# Curriculum workflow

The curriculum builder is context-first and subject-driven.

## Context

The current academic session is inherited automatically. The administrator chooses:

1. Term.
2. Section, using the class level/group.
3. Class.

Once the context changes, the builder immediately loads curricula already created for that session, term and class.

## Subjects

Existing subject curricula are displayed automatically.

Only subjects without a curriculum in the selected context appear in the selection area. System subjects are already available to tick. Custom subjects can be added from the same screen and are marked as school-specific.

Creating several selected subjects creates their curriculum records together. The administrator does not repeat the same class, term or session configuration for each subject.

## Weeks

Choose the number of weeks once. The selected subject plans receive the same weekly template.

Each subject gets a weekly plan with Week 1 through Week N. The administrator switches between subjects and fills the same week sequence for each one.

Each week has:

- topic/focus title;
- short coverage note;
- week number.

## Existing curriculum

If a curriculum already exists for the selected subject, open it directly. Do not create a duplicate. If it is missing, the subject remains available to select.

## Teacher handoff

Published curriculum is the source teachers use to prepare lessons. The intended path is:

Curriculum → Topic → Prepare lesson → Edit → Save → Publish.

The selected class, subject, session, term and topic should carry forward into lesson preparation automatically.

## Mobile rule

The entire builder is designed for phone first. Subject lists and subject tabs may scroll horizontally. Weekly rows stack vertically. Desktop-style multi-panel workbenches should not be introduced again.
